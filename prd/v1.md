# PortWatch PRD

## 1. 项目概述

**项目名称：PortWatch**

PortWatch 是一个基于 Go 开发的跨平台开发者端口管理与诊断 CLI/TUI 工具。

核心解决开发过程中常见的端口冲突问题：

> “8080 端口被谁占用了？”

传统方式需要执行 `netstat`、`tasklist`、`taskkill` 等多个系统命令。PortWatch 将端口查询、进程识别、进程详情、端口释放等操作统一到一个工具中。

核心理念：

> **发现端口 → 定位进程 → 理解进程 → 安全终止 → 验证端口释放**

第一阶段重点支持 **Windows**，架构设计上预留 Linux/macOS 支持。

# 2. 核心使用场景

### 场景一：开发服务启动失败

用户启动：

```bash
npm run dev
```

结果：

```text
Error: Port 8080 is already in use
```

用户执行：

```bash
portwatch 8080
```

立即看到：

```text
Port: 8080

PID       Process      Command
18232     java.exe     java -jar order-service.jar

Status: LISTENING
```

按 `K`：

```text
Kill process 18232 (java.exe)?

[Y] Yes  [N] No
```

确认后：

```text
✓ Process terminated
✓ Port 8080 is now available
```

# 6. 一键释放端口

提供：

```bash
portwatch free 8080
```

执行：

```text
Port 8080 is occupied.

PID:
18232

Process:
java.exe

Command:
java -jar order-service.jar

Kill this process?

[Y] Yes
[N] No
```

确认后：

```text
Terminating process...

✓ Process terminated.

Checking port...

✓ Port 8080 is now available.
```

### 安全要求

**默认不能直接 Kill。**

必须：

1. 展示进程信息
2. 用户明确确认
3. Kill 后重新检测端口

# 10. 开发服务识别

这是 PortWatch 后续非常重要的特色。

根据：

```text
进程名
命令行参数
工作目录
端口
```

尝试识别常见开发服务。

例如：

```text
3000
node.exe
D:\Projects\dian-web
```

识别：

```text
Framework:
Vite / Node.js
```

例如：

```text
8080
java.exe
java -jar xxx.jar
```

识别：

```text
Framework:
Spring Boot
```

例如：

```text
8000
python.exe
uvicorn main:app
```

识别：

```text
Framework:
FastAPI / Uvicorn
```

最终列表：

```text
PORT    PROCESS       SERVICE
3000    node.exe      Vite
8000    python.exe    FastAPI
8080    java.exe      Spring Boot
8848    java.exe      Nacos
4096    opencode.exe  OpenCode
```

**识别失败不要强行猜测，显示 `Unknown`。**

# 18. Windows 实现策略

第一版本优先实现 Windows。

可以利用 Windows 系统能力获取：

```text
TCP/UDP connection
PID
Process Name
Executable Path
Command Line
Working Directory
```

不要简单粗暴地全部依赖：

```powershell
netstat
tasklist
taskkill
```

**核心功能应该通过 Go / Windows API 获取。**

这样这个项目才真正有 Go 学习价值。

可以研究：

```text
golang.org/x/sys/windows
```

以及 Windows 网络/进程相关 API。

如果某些信息通过 API 获取成本过高，可以在 V1 使用系统命令作为 fallback，但代码层面要做好抽象。

# 21. Kill 的安全机制

这是项目必须认真处理的地方。

### 禁止默认：

```bash
portwatch
```

直接 Kill。

### Kill 前：

```text
⚠ Process Termination

PID:
18232

Process:
java.exe

Command:
java -jar order-service.jar

Port:
8080

This process may belong to another application.

Continue? [y/N]
```

### Kill 后：

```text
✓ Process terminated

Verifying...

✓ PID no longer exists
✓ Port 8080 is available
```

如果失败：

```text
✗ Failed to terminate process

Reason:
Access denied

Try running PortWatch as Administrator.
```

# 22. 错误处理

必须处理：

```text
PID 不存在
进程已经退出
权限不足
端口已经释放
端口不存在
访问被拒绝
管理员权限不足
Windows API 失败
进程信息无法读取
```

不要：

```text
panic()
```

然后直接退出。

给用户明确错误原因。

# 25. 最终产品定位

不要把 README 写成：

> “一个学习 Go 写的端口工具。”

而应该定位成：

> **PortWatch — A developer-friendly cross-platform port diagnostics and process management CLI/TUI.**

中文：

> **PortWatch 是一款面向开发者的跨平台端口诊断与进程管理工具，用于快速发现端口占用进程、查看进程上下文，并安全释放被占用的开发端口。**

核心价值：

```text
传统：

netstat
   ↓
PID
   ↓
tasklist
   ↓
taskkill
   ↓
netstat
   ↓
确认端口释放

PortWatch：

portwatch free 8080
        ↓
   自动完成全部流程
```

这就是这个项目最核心的卖点。
